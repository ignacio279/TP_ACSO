El código explota la bomba si los strings no coinciden, entonces la ingresé a esa frase como input para desactivar la fase.


PHASE_2 

En esta fase, el programa toma dos números enteros como entrada, primero, el programa evalúa si el producto entre ambos números es distinto de cero, despues, se verifica si la suma entre ambos números es igual a 0x3d83, que en decimal equivale a 15747. Finalmente, se llama a una función llamada misterio, que simplemente realiza un XOR entre ambos valores y verifica que el resultado sea negativo, la solución consiste en encontrar dos números que cumplan las tres condiciones anteriores. Para ello, elegí los valores -1 y 15748. Estos dos números multiplicados no dan cero (-1 * 15748 = -15748), la suma es exactamente 15747 (-1 + 15748 = 15747) y el resultado del XOR (-1 ^ 15748) es un número negativo, cumpliendo así con la condición requerida por la función misterio y con las otras dos condiciones.

PHASE_3

En la fase 3 vi que el programa espera como entrada dos valores: un string y un número, una vez que recibe eso, se llama a la función readlines, que carga una lista de strings desde un archivo externo. Luego usa cuenta(array, pattern, 0, n‑1), que recorre recursivamente esaas palabras contando cuántas veces aparece. Finalmente compara ese recuento con el entero n que introdujimos; si coinciden exactamente libera la memoria y la fase se desactiva.
La solución para esta fase es ingresar como string "aboquillar" y como número 10692. 
Sin embargo, esta fase tiene una particularidad, si se ingresan tres valores, y el tercer string es exactamente "abrete_sesamo", el programa detecta esta condición y activa una fase secreta. Esta funcionalidad está oculta dentro de la función phase_defused, la cual verifica si el contador de inputs leídos es 3 y el tercer string coincide con la palabra clave. De este modo, el input "aboquillar 10692 abrete_sesamo" permite acceder a la secret_phase, la cual solo puede ser activada desde esta fase.

PHASE_4 

En la fase 4, el programa primero verifica que la entrada sea una cadena de exactamente seis caracteres, despues el programa procede a analizar carácter por carácter. Para cada uno, extrae sus últimos cuatro bits mediante una operación `AND` con `0xF`, lo que equivale a tomar su valor módulo 16. Este número se usa como índice para acceder a un arreglo de 16 enteros ubicado en memoria. El valor obtenido del arreglo en esa posición se suma a un acumulador que comienza en cero.
Después de procesar los seis caracteres, se verifica si la suma acumulada es igual a `0x3E`, es decir, 62 en decimal. Si no se alcanza ese valor exacto, también se activa la bomba. Esto implica que la clave está en encontrar una combinación de seis caracteres tal que, al aplicarles la transformación mencionada y sumar los valores resultantes del arreglo, el total sea exactamente 62.
La cadena que cumple con esta condición es `013679`. Cada uno de estos caracteres tiene un valor ASCII cuyo residuo módulo 16 corresponde a índices específicos del arreglo. La suma de los valores en esas posiciones da como resultado 62, entonces cumplen con la condicion.

SECRET_PHASE 

Esta fase se activa como explique antes, la activé manualmente durante la phase_3 con un input "abrete_sesamo".
Una vez activada, el programa pide un número, lo convierte con strtoq, y luego lo pasa como argumento a la función recursiva fun7, que recorre un árbol binario comenzando desde la dirección de memoria 0x4f91f0.
El objetivo ahora es que fun7 devuelva 6 (cmp eax, 0x6). Como el recorrido en fun7 representa un camino codificado en binario donde ir a la izquierda es *2 y a la derecha es *2 + 1, tuve que encontrar el nodo tal que el camino recorrido hasta él devuelva 6.
Usando GDB, inspeccioné los punteros desde n1, siguiendo el árbol según los bits de 6, y encontré que el nodo con valor 35 es el correcto.
